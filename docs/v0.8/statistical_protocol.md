# resolved_rate 与实验记录

修订于 2026-09-23。本阶段比较固定 MCP 工具、提示和模型循环下的不同模型。
暂不实现重复择优、bootstrap、框架比较或行为分析。

## 计划与唯一主指标

运行前固定任务集合、模型配置、环境、提示、工具和预算。每个模型每题安排一次
求解，所有模型使用同一集合。分类仅是任务 metadata，不在运行器里改变评分。

```text
resolved_rate = resolved / planned
```

`planned` 是该模型本轮预先选定的逻辑任务总数，不是收到补丁数或成功执行数。
冻结补丁通过任务全部必需条件时 `resolved` 加一；同一缺陷的环境变体不增加分母。
任务没有准入标签、属于开发集或只选择一个子集，均可按声明计划计算修复率。
这不自动代表任务已审查或可以发布为正式研究结论。

报告按模型保存 `resolved_rate`、`planned`、`resolved`、`unresolved`、`missing`、
`errors` 和 `complete`。后几项是完成性与错误解释，不是其他主指标。没有题目的
计划不能作为一个有效比较实验；未知信息不补为通过或零费用。

## 完成性和异常

有可靠评分且没有解决的有效模型尝试记为 `unresolved`。计划单元缺少尝试记录时
记为 `missing`；已有尝试但评分证据缺失或不可信，以及模型服务、环境或评分流程
异常，记为 `errors` 并保留具体原因。存在未完成或无法确定的结果时 `complete` 为
false，报告显示 incomplete；当前比例只作进度，不能作为最终模型比较成绩。

服务响应已正确接收，但模型没有调用 `finish`、请求未知工具或提供非法参数，
属于模型在固定协议下的求解表现。系统结束该次求解，冻结已有补丁并独立评分；
有可靠评分时按结果记为 `resolved` 或 `unresolved`，与预算耗尽采用同样口径。
协议违规本身不直接判补丁错误，也不使一轮因模型未遵守要求而一直 incomplete。

请求超过剩余求解时间属于预算耗尽。其他 HTTP/模型服务故障、服务响应外壳损坏、
工具执行器故障、补丁无法可靠冻结或评分不可用，仍属于 `errors`，使报告 incomplete；
即使故障后冻结的补丁通过诊断性评分，也不计入 `resolved`。普通公开构建或测试失败
是可返回模型的反馈，既不是任务已解决的证明，也不自动属于基础设施错误。

10 题解决 6 题，另有 2 题环境故障时，当前比例仍为 6/10，不改成 6/8；同时明确
该轮未完成。不能将所有基础设施错误解释成模型能力失败，也不能为提高成绩
事后删除计划任务。超时终止和截止时冻结补丁是否通过分别记录。

模型、公开输入或实验预算需要修改时另建计划。环境故障修复后是否可继续原
计划，依据保存的阶段和不可变输入判断，不能以恢复名义替换题目或求解条件。

## 恢复、重评和报告重算

- 恢复使用已有输入和记录；已有尝试不隐式重跑，残留的 `running` 记录改为 `interrupted`。
- 同一冻结补丁的独立重评保存来源、原因和新结果，不增加任务样本，也不覆盖原失败或自动替换原报告成绩。
- 重新调用模型解决同一道题属于新的实验，不反复尝试后只保留成功结果。
- `report` 只读取计划和结果，生成当前报告；不在读取时修复、补写或修改原始运行记录。

```bash
opbench report --run runs/v0.8/validation/quickstart-r1/controlled-models
```

完整评分只保存在 `evaluation/result.json`；尝试与重放记录保存关联路径。读取时
核验评分证据、题目身份与冻结补丁，不使用旧记录中的内嵌评分缓存。
多环境父结果和控制组也仅引用各自独立的子评分文件，不重复保存测试详情。
旧 `agent/model` 标签和终态别名只在记录读取入口转换，原始文件保持不变；报告
使用统一字段，当前报告协议为 5。缺少明确冻结声明的旧尝试不能恢复为可信成绩，
也不支持 `replay`；当前报告不聚合旧多重复计划。
实验结束或中断时汇总一次；运行中可手动执行 `report` 查看进度。两者使用同一
计算函数，避免每完成一题就重新核验所有历史评分。重算覆盖派生的 `report.json`，
不维护额外的报告历史版本。实际重评则必须保存原因和独立输出，保留原尝试及评分。

报告生成身份和原执行身份分开。重新计算报告不能证明补丁重评、环境重建或模型
重跑可得到同样输出。旧原生运行与旧多重复统计仍按原协议保存，不能用新字段
默认值将其升级为本轮固定 MCP 模型实验。
批次目录、失败记录和缓存的保存约定见[运行记录](../../runs/README.md)。

## 保留轨迹，暂不分析

每个尝试保存模型请求与回复、工具名和参数、工具结果、阶段耗时、终止原因、
冻结补丁及最终评分的对应关系。凭据不进入轨迹。用量有来源才记录，缺失的 token
或费用保持未知；不将 CLI 自报用量当作服务账单。

这些记录供复核与后续行为分析使用，本轮不实现策略诊断或优化建议。v0.10 开展
统一实验时，需先冻结配置并保存完整计划；跨框架比较和更复杂推断留到后续。
