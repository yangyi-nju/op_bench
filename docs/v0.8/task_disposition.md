# v0.7 历史 50 题的 v0.8 处置初审

原始审阅日期：2026-09-09，导航说明更新于 2026-09-23。结构化原始结果见
[historical_review.json](../../datasets/v0.8_candidates/historical_review.json)。按[当前版本范围](design.md)，
本初审是 v0.9 数据建设的输入；下文分类和“主分”建议不代表当前运行器已实现类别筛选或正式准入。

仓库精简后，旧题的题面、源码 commit、参考/测试补丁和处置记录继续作为重制素材保留。旧 task.json 不是新 CLI 的可执行任务包；旧工厂、环境注册表和源码注册表的执行路径已移除，历次发布与设计文档保留在[版本历史](../history/README.md)，对应运行资产可查阅 [v0.7 发布提交](https://github.com/yangyi-nju/op_bench/tree/55c8ef2bd7d0bf78fc26bfd25498d9252e70781f)。旧字段指向已删除运行资产时只作历史声明，不代表新环境可用。

**这是一份逐题静态语义初审，不是正式准入。** 本轮读取了 50 题的题面、公开约束、评分选择器、参考补丁改动与测试补丁；对争议和高风险题另读旧质量记录。没有运行 PyTorch、编译、GPU、Agent 或控制组，没有独立人工审查，也没有修改旧题或继承旧 `verified`。本轮准入数为 **0**。

覆盖层次来自所读测试代码实际调用的入口，不表示这些测试已经运行成功。未完整审阅源码树中未出现在补丁内的既有回归函数，也未联网核对每个上游 PR 的完整原始内容。表中“参考”指当前仓库提供的参考补丁，其正确性仍需重新验证。

## 审阅范围与结论

[pytorch_v0.7](https://github.com/yangyi-nju/op_bench/blob/55c8ef2bd7d0bf78fc26bfd25498d9252e70781f/datasets/pytorch_v0.7/dataset.json) 为 50 题；boundary、device、precision 分别为 31、15、5 条成员记录，与主集合并后仍为同一 **50 个 task_id**。四个视图不能相加成 101 道题。

| 静态语义范围 | 题数 | 含义 |
| --- | ---: | --- |
| 算子本体 `operator` | 5 | 公开计算、参数或存储行为缺陷 |
| 算子执行链路 `operator_integration` | 33 | 直接相关的编译、自动微分、导出、分派等缺陷 |
| 框架支持 `framework_support` | 9 | 模块/数据加载/优化器及开发测量工具，单独归类 |
| 范围待定 `uncertain` | 3 | 当前材料不足以建立具体算子执行联系 |

因此，不能说现有集合主要是通用框架维护题；**38 题的主题与算子本体或执行链路有关，但主题相关不等于测试已经充分验证了它。** 其中 37 题建议作为主范围重制候选，另 1 题先厘清资源回归与优化合同；9 题单列支持范围，3 题暂缓范围判断。候选并不保证最终保留，独立审查或控制组可能要求进一步拆分、合并、改写或撤除。

所读测试中，19 题包含其声明工作流的端到端入口代码，20 题包含内部 helper 调用，12 题使用替身/mock；这些标签可重叠，且含支持题，不能作为“19 题已完成端到端验收”的结论。完整逐题标签和选择器保存在 JSON 中。

## 贯穿全表的整改要求

- 每题公开合同与必需测试双向对应；新增内部函数名、参数名、代码字符串或参考补丁结构不能无依据地成为正确答案条件。
- 公开求解、冻结补丁、干净候选构建与可信判定分别管理；候选构建不接触私有 grader。用真实加载与行为证据替代旧 Gold 路径白名单和文件级校验。
- 真实验证基线、参考修复、相关回归与语义错误变体；高风险题验证合理替代解，其他题记录公平性审查理由，不机械要求每题第二份补丁。
- 旧配置中 47 题声明 `python_overlay`、3 题声明源码构建。这只是历史配置事实；逐题分类依据题面、补丁与测试，未使用这些标签推断能力或准入。真实基线、依赖、构建加载和设备路径都要重验。
- 数值题需要有效输入域、容差和独立参考；元数据题可以只要求元数据，但不能据此宣称已验证数值或梯度。
- 来源、开发暴露、数据划分及关联缺陷组仍需审查。没有依据只因同一目录、组件或运算名就合并为同源组。当前 JSON 的分组均为待审，未杜撰独立性证据。
- 上游资产的归属和可使用范围继续审查；OpBench 自有代码许可证仍待与学校确认。本表不授权公开发布。

## 需要优先处理的证据问题

1. **参考实现被隐藏断言固定。** #179333 要求新增 `index_dtype_override` 构造参数，#178667 要求新转换 handler 的名称与分发表身份，#186008 要求题面未给出的配置名。旧复杂度记录甚至把“不透露参数名”作为优点；新协议必须修正公开规格或替换这类断言。
2. **“可以执行”只由字符串相等代替。** #179708 的 `is_executable` 用例没有执行 Python 表达式或编译 C++。#176922、#182825、#185257、#188485 同样以生成文本代替包装器/运行时行为。局部测试有诊断价值，但不能代表声明的真实路径。
3. **参考修复本身有待核查的行为缺口。** #181119 的输入 view 带有不同 storage offset，参考补丁生成 `as_strided` 时没有传入 offset，测试又只检查共享指针；从代码看可能丢失相对视图位置。需要明确输入关系合同并重审参考，不能仅因历史 Gold 通过就接受。
4. **性质或探针过弱。** #144009 只查归一化，不能排除错误的均匀分布；#180298 只断言失败探针返回 False，缺少真实失败控制；#162340 的单一选择器没有覆盖题面要求的全部参数长度语义。
5. **动态、梯度与资源声明需分开举证。** dynamic_shapes 声明不等于同一产物已跨 shape 执行；requires_grad 标志不等于梯度数值正确；Python Sentinel 被释放不等于 CUDA 内存已释放。
