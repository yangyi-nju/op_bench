# 固定工具框架的信息边界

本轮使用可信控制器中的固定模型循环与 MCP 工具，取代任意原生 Agent 启动及
容器推理网关。工具与循环的共同规则见[接入说明](agent_integration.md)。
下述文件和网络隔离适用于 `controlled` Docker 执行。`development` local 调试
仍使用同一工具协议，但候选代码在宿主执行，不具备这些隔离保证。

## 资产如何分配

| 位置 | 可以持有什么 |
| --- | --- |
| 可信控制器 | 完整任务包、参考修复、私有 grader、模型客户端与凭据、执行计划和结果 |
| 模型上下文 | 公开题面、固定工具说明、模型此前消息及工具返回的公开工作区信息 |
| 求解 Docker 工作区 | 指定基线源码、公开复现、预置依赖、模型修改及自测产物 |
| 独立评分阶段 | 冻结补丁的候选构建与所需评分资产；隐藏结果不返回已结束的求解 |

工具处理路径必须限定在分配工作区，不允许通过绝对路径、父目录或符号链接读取
控制器文件。模型不能通过工具要求宿主运行任意命令。构建与公开测试会执行候选
代码，它们在断网容器内运行，不挂载 Docker socket、宿主用户目录或凭据。
MCP 接口保持薄，不把受控工具本身当成安全沙箱。

## Git、网络与反馈

Git 源码从任务指定修订导出；目录来源则复制为无 Git 历史的快照，需另行记录
目录来源。求解所需本地版本记录由干净初始仓库建立，不携带上游 Git 对象或
remote，不能沿历史找到后续修复。其他尝试和参考补丁不放入公开工作区。
基线和镜像作者还须避免在源码或预置文件中夹带答案。

源码获取和依赖准备在求解前显式进行。求解工作区没有联网能力，模型调用由
控制器完成；不为候选提供网络代理、外部搜索、托管工具或模型服务凭据。
因此无需模型网关或 relay。模型客户端同样不启用搜索或额外工具框架。

公开测试反馈可用于求解。最终私有评分在停止求解并冻结补丁后进行，只向实验
操作者报告；恢复不能把隐藏结果接回同一次循环继续修复。重新求解需另建实验，
不能静默升级原尝试的条件。

## 保证范围

本轮验收检查输入隔离、工具路径和实际执行边界。Docker 不是对任意内核漏洞的
证明。固定工具也不能证明模型没有记忆公开题目的答案。模型服务、镜像及任务资产
的可信来源属于部署前提。

数值参考能够在候选执行结束后独立比较；共享框架进程的评分仍有明确的防干扰
局限，见[任务指南](task_format.md)。这些限制应随实际实验条件记录，而不是靠
文件 hash 或模型的自我声明消除。
