# OpBench v0.7 P3 Boundary Tasks Design

日期：2026-07-27

状态：Approved for implementation。用户已授权在不逐项确认的前提下完成整个
v0.7，并由实现者选择最优工程方案。

## 1. 目标

P3 从真实 PyTorch 修复中制作 6 条 Boundary Task，使用 P1 已冻结的
Candidate/Decision/Factory Admission 合同和 v0.6 Admission Protocol，最终只把
同时满足 Baseline Failure、Gold Success、P2P Kept、Test Executed、Scope 和
Integrity 的任务标记为 verified。

数量不是降级 Admission 标准的理由。任何候选在 source、runtime、test 或根因
审查上失败时保留稳定拒绝证据；只有仍有 4–6 条 verified Task 时 P3 才 Passed。

## 2. 方案选择

评估了三种方案：

1. **均衡 6 项（采用）**：5 条 Python/Inductor overlay 与 1 条 C++ source-build，
   覆盖 B1–B5；B5 使用低内存 surrogate。优点是 taxonomy 完整且实时成本受控，
   风险是需要维护多个历史 wheel compatibility。
2. **Python-only 4–5 项**：实现最快，但只能可靠覆盖 B1/B2/B5，B3/B4 缺口过大，
   Boundary Slice 的解释力不足。
3. **每类 kernel-heavy**：每类都选择底层 C++/CUDA 修复，根因直接但需要多个
   exact-source build，Admission 成本和环境漂移风险不成比例。

均衡方案保留一个真实 C++ overflow Task 来证明 Factory 不只服务 Python overlay，
其余任务使用最小冻结源文件和可重复 runtime。它不使用真实 OOM、大 tensor 分配、
随机 allocator 状态或不可控 timeout。

| #117065 | `b9293e74a2b476534fa2aee5a0708e3fca255d8e` | B2 | `torch/_decomp/decompositions.py` | exception | CPU Python overlay |
| #126461 | `15ca562f863ffe69d76c0ccaf448b27d18ceb2e8` | B2 | `torch/_inductor/lowering.py` | exception | CPU Python overlay |
| #147352 | `6ccbff1450bb3936636377d3910906f5666ddcfa` | B3 | `aten/src/ATen/native/Resize.h` | exception | CPU source build |
| #118762 | `e426924c19500011aa419accc251a923fe857b94` | B4 | `torch/_decomp/decompositions.py` | exception | CPU Python overlay |
| #139751 | `cc98a1b59909e6f3ce929380e02f0345c862e31d` | B5 | `torch/_inductor/codegen/triton.py` | wrong-result | CUDA Python overlay |

人工根因结论：

- **#143792 / B1**：zero-size matrix 的 `mv` 结果为空，但 `beta * self`
  仍应保留；decomposition 直接返回空结果会与 eager `addmv` 不一致。
- **#117065 / B2**：0-d index 必须先升为长度 1 的 index vector，才能与
  `index_put` 的索引语义一致。
- **#126461 / B2**：rank-0 `cummin/cummax` lowering 不能在 lowering 阶段调用
  eager `torch.empty_like`；必须使用 Inductor lowering primitive。
- **#147352 / B3**：storage offset 与 itemsize 的乘加可能溢出；同一
  `computeStorageNbytes` checked arithmetic 必须覆盖 offset。测试只使用小 tensor
  和极端整数，不分配大 storage。
- **#118762 / B4**：`aten._weight_norm_interface` 的 API 默认 dim 为 0，
  decomposition 漏掉同一 parameter endpoint，导致调用默认参数时 TypeError。
- **#139751 / B5**：Y grid 被折叠到 Z grid 且不是整除时仍需要 ymask；把 mask
  错误常量化会让尾块越界。测试直接检查 `_has_constant_mask` 的判定路径，不创建
  上游回归测试中的超大 CUDA tensor。

GitHub PR API 对部分 ghstack landed PR 显示 closed/unmerged。Merge identity 必须
使用 PyTorch 主干中带 `Pull Request resolved` trailer 的 landed commit，而不是
PR 临时 head/base ref。

## 4. 明确拒绝与延后

P3 的真实候选捕获还包括以下负样本，确保 funnel 不是只记录成功项：

- #143461：标题和根因命中 B1 frozen pack 的 `empty list` exclusion，拒绝
  `taxonomy.not_boundary`；
- #147433：修复进入主干后被 revert，拒绝 `review.upstream_reverted`；
- #127448：5 个文件且包含测试重写，自动筛选为
  `change.large_diff_requires_review`，本阶段 defer；
- #139502：1 行改动且无 executable test delta，拒绝
  `test.missing_executable_delta`。

P1 的 Decision reason code 保持不变。P3 人工审查的新 reason code 只出现在
review report，不反向修改冻结筛选规则。

## 5. Factory 数据流

```text
local git log + GitHub structured metadata
  → real candidate capture
  → CandidateRecord / DecisionRecord
  → immutable Factory Artifact Store
  → curated Task bundle
  → preflight
  → Baseline/Gold Admission evidence
  → human review record
  → FactoryAdmissionRecord(verified or rejected)
```

`factory_screen_candidates.py` 需要从“固定 synthetic fixture”扩展为通用的本地
capture reader，但不执行网络请求。每条 capture 明确提供
`discovery_source`、可选 `external_test` 和可选 `environment_freeze`；缺省值只为
旧 fixture 保持 `fixture` compatibility。原始 GitHub 响应不进入公开 Task View，
公开 Candidate 仅保存有界 provenance 和内容哈希。

新增 `factory_promote_admission.py` 只消费已存在的 Candidate、Decision、Task、
Admission evidence 与 human review JSON。它必须 fail closed：

- Decision 不是 accepted；
- Task 不是 verified；
- Admission replay hash 与当前 bundle 不一致；
- Baseline/Gold/F2P/P2P/collected-executed 证据不完整；
- human review 未批准或 taxonomy/scope/surrogate 任一项未确认；
- Artifact 引用类型、ID、hash 或相对路径不一致。

上述任一条件都不得生成 verified FactoryAdmissionRecord。

## 6. Task Bundle 设计

每条任务包含：

- 规范化 `task.json`、`issue.md`；
- 从 landed commit 精确提取且只保留 allowed source path 的 `gold.patch`；
- evaluator-only `hidden_test.patch`，F2P 与 P2P 均有显式断言；
- Candidate/Decision provenance 引用；
- `operator.problem_dimension=boundary`、B1–B5 subclass 和 failure contract；
- task-local `admission/evidence.json`；
- task-local `factory/admission.json` 与 `factory/review.json`。

Agent Patch Scope 与 Gold source path 完全一致。上游 test patch 只作为设计依据；
Hidden Test 使用独立测试名和最小输入，不能把修复实现或 Gold diff 暴露给 Agent。
Issue 只描述用户可观察语义、复现条件和允许路径，不给出具体修复语句。

F2P/P2P 设计：

- #143792：F2P 比较 compiled/decomposition 与 eager zero-size addmv；P2P 覆盖
  非空矩阵和 `beta=0`。
- #117065：F2P 运行 0-d index 的 index-copy decomposition；P2P 覆盖 1-d index。
- #126461：F2P 编译 rank-0 cummin/cummax；P2P 覆盖普通 1-d cumulative reduction。
- #147352：F2P 断言极端 storage offset 抛出受控 overflow exception；P2P 覆盖
  正常 as_strided 和 zero-size 任意 offset 语义。
- #118762：F2P 省略 dim 调用 decomposition 并与 native 结果比较；P2P 显式传
  `dim=1`。
- #139751：F2P 构造 y-grid overflow/non-divisible fake range tree，断言不能使用
  constant ymask；P2P 覆盖 X grid、未超限 Y grid 和已有 Z grid。

## 7. Runtime 与 Source 策略

环境顺序复用 P2 原则：匹配官方 wheel → exact source-built wheel → full source
build。Python overlay 任务必须先运行 Compatibility Probe，证明目标模块来自
Base Commit 且 selector 可收集。不能因 wheel API 代差改写 Hidden Test。

- 2024-01/05 base 优先 torch 2.2/2.3 cp311 CPU matched wheel；
- 2024-12 base 优先 torch 2.6 cp311 cu124 matched wheel；
- 2025-02/03 base 优先 torch 2.7 cp311 CPU/CUDA matched wheel；
- #147352 因修改 C++ header，使用 exact Base Commit source build，并冻结 build
  flags、compiler、artifact digest 和 ccache key；
- #139751 在现有 sm_70+ GPU 执行 import/selector check，但 F2P surrogate 不分配
  大 GPU storage。

若 matched wheel 的 public API 缺失导致无关失败，按 Compatibility stable failure
code 进入下一策略；不得把 compatibility failure 计作 Baseline Failure。

## 8. 错误处理与安全边界

- 所有候选、Decision、review 和 admission artifact append-only，CLI 拒绝覆盖；
- 原始日志写入 ignored run directory，公开证据只保留有界摘要和 hash；
- crash/OOM/timeout 不是这 6 条任务的预期 F2P；
- selector collected/executed 数不等于声明数时 `test_not_executed`；
- CUDA surrogate 必须由 review 明确确认调用同一生产方法、相同 predicate 和相同
  Gold 修改路径；
- source build 失败、wheel incompatibility、上游 revert 和 flaky failure 分开归因；
- 未满足 4 条 verified Task 时 P3 失败，不从 rejected/deferred 候选补数。

## 9. 测试与验收

平台改动使用 TDD，至少覆盖：

- real capture 的 discovery source/external test/environment freeze round trip；
- 旧 synthetic fixture 输出逐字节兼容；
- Factory Admission promotion 的每个 fail-closed gate；
- FactoryAdmission Schema 与 Python contract 一致；
- review/rejection funnel 确定性；
- 6 个 Task manifest、patch scope、taxonomy 和 replay hash。

每条真实 Task 必须通过：

1. Task/Schema validation；
2. Source/Environment/Compatibility preflight；
3. Baseline F2P 全失败且 P2P 全通过；
4. Gold F2P/P2P 全通过；
5. declared selectors collected/executed，无 skip/xfail；
6. human review 与 FactoryAdmission promotion；
7. fresh replay hash 对比。

P3 结束时运行 focused tests、全仓 unittest、compileall、tracked JSON、v0.5 Dataset
兼容验证和 `git diff --check`。报告精确数量、duration、任务结论、拒绝 funnel 和
未降低标准声明。
