# OpBench v0.7 P5 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish OpBench v0.7 as a reproducible 25-task Dataset Factory and Boundary Slice release with a complete Dataset Card, consistent bilingual entry points, and verified non-leaderboard wording.

**Architecture:** Treat the already frozen P4 Dataset and validation report as the only release data sources. Add one release-document test module that checks counts, links, completion state, and safety wording; then write the Dataset Card and update the existing English/Chinese entry points and milestone records. Finish by rebuilding every generated v0.7 artifact and running the repository-wide release gate.

**Tech Stack:** Markdown, canonical JSON artifacts, Python 3.12 `unittest`, existing Factory/Dataset/Runtime validation CLIs.

## Global Constraints

- Release identity is `opbench-v0.7.0`.
- Cumulative Dataset is exactly 25 verified Tasks.
- Boundary Slice is exactly 6 verified Tasks and covers B1–B5.
- Precision Slice is exactly 8 verified Tasks and covers P1–P5, including two P4 Tasks.
- Candidate funnel is exactly 10 candidates: 6 accepted, 2 deferred, 2 automatically rejected; human review rejects the reverted #147433 and leaves #127448 deferred.
- The public validation result is descriptive Task/platform evidence, not a formal cross-Agent leaderboard or feedback-causality result.
- Public artifacts must not contain private hosts, target paths, credentials, raw private evaluator output, or controller-only files.
- No Admission threshold, Task test, Dataset membership, Agent identity, model identity, or scoring rule may change during P5.
