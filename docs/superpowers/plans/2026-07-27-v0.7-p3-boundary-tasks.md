# OpBench v0.7 P3 Boundary Tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Subagent execution is disabled for this repository session.

**Goal:** Produce 6 evidence-backed verified PyTorch Boundary Tasks covering B1–B5 and preserve a deterministic accepted/deferred/rejected Factory funnel.

**Architecture:** Extend the offline screening CLI to accept bounded real-candidate captures without adding network behavior, then add a fail-closed Factory Admission promotion layer over the existing immutable lifecycle contract. Curate six independent Task bundles from ghstack-aware landed commits, resolve each historical runtime using the matched-wheel/source-build order, run fresh Baseline/Gold Admission, and materialize final Factory Admission chains.

**Tech Stack:** Python 3.11/3.12, unittest, dataclasses, Draft 2020-12 JSON Schema, PyTorch official wheels, Docker/RemoteDocker, Git sparse/full snapshots, existing OpBench v0.6 Admission and v0.7 Factory contracts.

## Global Constraints

- Do not change a selected PR's landed commit, Base Commit, root-cause category, or source fix.
- Do not use real OOM, huge tensor allocation, random allocator state, skip, xfail, or uncontrolled timeout as F2P.
- Agent Patch Scope must equal the curated Gold source paths and exclude all evaluator test paths.
- Compatibility evidence is separate from Baseline Failure and cannot replace Admission.
- Every declared F2P/P2P selector must be collected and executed.
- Public artifacts contain bounded metadata and hashes only; private logs remain under ignored `runs/`.
- Promotion is fail closed and never edits a Task before every input contract validates.
- P3 passes only with 4–6 verified Tasks; failed candidates retain stable evidence and are not relabeled.
