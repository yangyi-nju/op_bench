# OpBench v0.7 Quality-First 50-Task Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reopen OpBench v0.7, re-admit the historical 25 Tasks under
non-leaking Prompt and complexity gates, expand the verified Dataset to exactly
50 medium/hard Tasks, and publish reproducible cumulative, Precision, Boundary,
and Device views with complete validation evidence.

**Architecture:** Keep the existing FullTaskSpec → AgentTaskView isolation and
v0.7 Factory history intact. Add focused quality modules for taxonomy, Prompt
evidence, complexity evidence, archive identity, and quality-release
composition; final v0.7 Tasks reference these artifacts while the canonical MCP
Adapter receives only an opaque public Task identity and sanitized
AgentTaskView. Execute release work as a strict pipeline: freeze old truth,
install gates, re-admit historical Tasks, capture and admit a 3× candidate
funnel, freeze 50 Tasks, run replay and Agent cohorts, then close documentation.

**Tech Stack:** Python 3.11 standard library, frozen dataclasses, canonical JSON
and SHA-256 identities, JSON Schema artifacts, `unittest`, Git, existing
Local/Docker/Remote Runtime Profiles, and `codex_mcp_canonical`.

## Global Constraints

- Final release identity remains `opbench-v0.7.0`; the old completed state is
  archived as `v0.7-pre-quality`.
- The pre-quality baseline commit is exactly `4f5addc`.
- The final cumulative Dataset contains exactly 50 unique verified Tasks.
- Hardware scope is CPU and NVIDIA CUDA only; MPS, XPU, multi-node workloads,
  and other accelerators are excluded.
- Required taxonomy fields never accept `unknown` or `other`; optional tags may
  be absent.
- Precision, Boundary, and Device are derived overlapping slices, not primary
  mutually exclusive categories.
- No final Task is `easy`; complexity totals 0–3 reject, 4 requires a blind
  pilot and second review, and 5–6 are eligible.
- The Agent sees only an opaque ID matching `opbench-v07-t[0-9]{4}`, sanitized
  behavior, public tests, runtime facts, and repository-root editing
  capability.
- The Agent never receives PR/Commit provenance, Gold or Hidden assets, private
  Patch Scope, exact target paths added as guidance, internal repair symbols,
  root cause, or solution instructions.
- `CapabilityPolicy.writable_paths` is `(".",)` for every final v0.7 Task;
  `FullTaskSpec.patch_scope` remains private and is enforced after complete diff
  capture.
- All 25 historical Tasks receive a documented retain/defer/retire
  re-admission disposition; no historical Task is silently dropped.
- Historical pre-quality Attempts are not reused as final validation.
- Every retained historical Task receives one independent final Agent attempt.
- Every new or replacement Task receives three independent final Agent
  attempts.
- Score-4 blind pilots are Admission evidence and never count toward final
  validation repeats.
- All 50 Tasks receive fresh Source/Runtime, Baseline, Gold, F2P, P2P, Prompt,
  complexity, taxonomy, and Integrity checks.
- Final hard coverage gates are CPU ≥30, CUDA ≥15, compile ≥8, and
  backward/Autograd ≥6.
- Soft composition targets are result 10–12, tensor_metadata 9–11,
  mutation_state 7–9, gradient 7–9, api_behavior 6–8, and
  efficiency_safety 4–6.
- Derived-slice targets are Precision 10–14, Boundary 10–14, and Device 15–20;
  gaps are reported rather than filled by lowering Admission standards.
- The post-audit candidate pool contains at least `3 × (50 - k)` real
  candidates, where `k` is the retained historical count.
- Agent reasoning text is neither collected nor scored in v0.7.
- The repository stays dependency-free; do not add third-party Python
  packages.
- Every generated JSON artifact is canonical, content-addressed where
  applicable, and reproducible byte-for-byte.

```python
def derived_slices(taxonomy: TaskTaxonomyV2) -> tuple[str, ...]:
    selected = set()
    if (
        taxonomy.contract_family == "result"
        and "numerical" in taxonomy.contract_detail_tags
    ):
        selected.add("precision")
    if set(taxonomy.trigger_tags) & BOUNDARY_TRIGGER_TAGS:
        selected.add("boundary")
    if (
        "cuda" in taxonomy.execution_context.devices
        or "device" in taxonomy.contract_detail_tags
    ):
        selected.add("device")
    return tuple(sorted(selected))
```
