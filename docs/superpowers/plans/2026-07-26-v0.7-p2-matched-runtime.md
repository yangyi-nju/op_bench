# OpBench v0.7 P2 Matched Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce auditable matched-runtime conclusions for PyTorch #129154 and #144073, restoring each task only after compatible-runtime evidence and full Baseline/Gold Admission agree.

**Architecture:** Add a focused `op_bench.matched_runtime` package containing an immutable compatibility contract, a probe orchestrator and a fail-closed promotion gate. Reuse the existing Task, EnvironmentManager, source-loading and Admission implementations for real execution, while keeping compatibility classification separate from F2P/P2P classification. Prefer retained official wheels and fall back to exact-commit content-addressed source builds only when a wheel probe fails.

**Tech Stack:** Python 3.11+, frozen dataclasses, canonical JSON/SHA-256, JSON Schema draft 2020-12, unittest, Docker, SSH/rsync, PyTorch official wheels, ccache.

## Global Constraints

- Do not modify either task's Base Commit, target source path, Hidden Test, Gold Patch, F2P selector or P2P selector.
- Do not monkeypatch missing APIs, weaken tests, add skips or convert unrelated import/build failures into task failures.
- Compatibility evidence cannot substitute for Baseline/Gold Admission.
- `compatible` requires target-module byte identity with the Base Snapshot and a present runtime artifact digest.
- Try `matched_wheel`, then `source_built_wheel`, then `full_source_build`.
- Store no secret, remote host address, absolute private path or raw container handle in committed evidence.
- Only registry assets that were actually built or observed may be committed.
- Use one fresh evaluation workspace per Baseline and Gold run.

```python
workspace_error = evaluator.prepare_workspace(task, workspace, commands)
```

The runtime identity command emits one JSON line containing only public

The target-provenance command imports the configured module, resolves
`module.__file__`, hashes its bytes and compares it with the already-computed
snapshot target hash. Store only the workspace-relative suffix and hash.

The selector command imports the test module and uses
`unittest.defaultTestLoader.loadTestsFromName` for every declared selector. It
fails when the suite count differs from one or contains `_FailedTest`.
